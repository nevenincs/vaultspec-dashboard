# Dev workflow: full gate, revision precedence, explicit ports

- **Declaring green runs the full gate.** Before reporting a change green, committing it, or routing it to review, run the FULL lint gate for the touched language — `just check-frontend` (eslint + prettier + tsc) or `just check-all` (adds Rust `cargo fmt --check` + clippy) — and confirm exit 0. A partial run (eslint-only, clippy without fmt) is not green. The reviewer runs the full recipe independently; a prettier- or rustfmt-dirty file is a withhold regardless of logic.
- **Green includes the tests, not just the lint gate.** The lint gate never invokes vitest or cargo test, and the frontend-localization campaign accumulated SIX live instances of red tests hiding behind a green lint report (codified from its `S108` closing review). Before reporting green or ticking a step, ALSO run the touched-scope test suites (`npx vitest run <touched dirs>` / `cargo test -p <touched crate>`), and run the full `just test-frontend` / `just test-rust` before routing a phase to review or closing a plan. Never run two full vitest suites concurrently against one live engine — the authoring apply lock makes a test flake spuriously. One caveat the campaign adjudicated: component unit tests that isolate data/store dependencies via mock while resolving copy through the real localization runtime are a permitted carve-out from the live-wire test rule; mocking the localization runtime, catalog resolution, or the engine wire itself stays forbidden.
- **Required revisions block forward work.** When a phase review verdict is withheld or carries required revisions, the revision commit must land and pass the reviewer's re-check before any forward phase work begins. Review service is withheld for work executed past that block.
- **Dev/test servers bind explicit non-default strict ports, declared once.** Every long-lived dev/test server binds a port declared in the `portless` / `devserver` block of `frontend/package.json` (this app's block is 5320-5339), read through `frontend/dev/dev-ports.ts` `DEV_PORTS`, with `strictPort: true` / fail-loud-on-conflict — never a framework default (Vite 5173), never drift-to-next-free, and never a port literal in a justfile, Vite, Vitest or Playwright config. SPA = 5320, engine = 5321, visual review = 5322, adverse = 5324, perf = 5325; env-overridable via `VAULTSPEC_DEV_*_PORT`. The one exception is the vitest live-engine harness (OS-assigned ephemeral port). Start, reattach and stop servers only through `just dev` (the machine-wide harness `dev/devserver.py`: `just dev`, `just dev up review`, `just dev status`, `just dev stop all`) — it clears stale or foreign servers on the declared ports itself, so never kill processes by hand. Verify live work ONLY against the declared ports (or `https://vaultspec-dashboard.localhost` through portless), and treat any vaultspec server on another port as stale/foreign. The installed product engine's default port (8767) is not a dev port.
