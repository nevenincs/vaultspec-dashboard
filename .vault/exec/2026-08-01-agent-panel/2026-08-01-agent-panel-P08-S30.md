# Build ClarificationCard (choice buttons, bounded text inputs, required gating) rendered at the park point with the composer disabled with a hint

## Scope

- `frontend/src/app/agent/ClarificationCard.tsx`

## Description

- Build ClarificationCard bound to the D5 payload: choice questions as radio-pill groups, text questions as single-line inputs (never a textarea - the engine rejects control characters), required gating submit, rendered in-transcript at the park point with the composer disabled-with-hint from the same authoritative disclosure.
- Three no-stranding refusals: an id-less or prompt-less question is dropped, an optionless choice degrades to text so it stays answerable, and a request with nothing answerable yields no card at all.

## Outcome

Landed in commit cf7da119ed with the durability fix in c7b99e5cb2. Independently reviewed twice: the first pass confirmed payload binding, park semantics, recovery authority, and fail-closed behavior, and BLOCKED on the recap evaporating; the re-review confirmed the fix closed it cleanly with no regression to any confirmed item.

## Notes

This surface has no reference-app precedent; the unverified-by-reference marker lives in the ADR, the component header, and the live-drive plan step. A narrow double-submit window (the card stays enabled between success and the refetch unmount) is recorded as a low-severity follow-on - the respond path is idempotent and a stale respond is refused, so the cost is cosmetic.
